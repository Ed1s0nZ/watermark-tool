## 真实图片与原图保护

使用花朵照片（500×477）、人像照片（512×512）、咖啡静物（600×400），固定 URL 和预期 SHA-256。每例从只读原图复制独立输入，水印输出与压缩分支位于独立 run/case 目录。原图处理前后逐一核对哈希，三者均不变。复现命令：

```bash
go run ./cmd/blind-bench -dir /tmp/watermark-go-bench
```

工具标准库下载，大小/超时受控；缓存文件也验证摘要。不符合预期样本时失败，不静默替换图片。嵌入使用固定公开测试密钥和固定时间以保证协议/画质可重复；生产密钥由 CLI crypto/rand 生成。输出目录新建，已有原图不作为输出；基线或负例失败会产生非零退出状态。不同质量分支不累积重编码。

最终 [Markdown 报告](benchmark.md) 与 [JSON](benchmark.json) 来自 `/tmp/watermark-go-research/run-4100742127/`。照片保留在外部临时目录，不入库、不随代码分发。来源与样本 SHA 载于报告；Wikimedia 花朵来源页和 scikit-image v0.19.3 数据集保留各自的来源/授权，不将下载样本冒称自制。入库图片夹具完全自制，附公开测试密钥，禁止用于生产。

| 项目 | 观测 |
| --- | --- |
| PNG 重新编码 | 3/3 完整载荷恢复 |
| JPEG quality 95 | 3/3 完整载荷恢复 |
| JPEG quality 85 | 3/3 完整载荷恢复 |
| JPEG quality 75 | 3/3 完整载荷恢复 |
| 无水印图片 | 3/3 拒绝 |
| 错误密钥 | 3/3 拒绝 |
| 原图 SHA-256 | 3/3 不变 |

报告 PSNR 比较原图解码 RGB 与处理后解码 RGB，同时含水印和 JPEG 失真；不把它当作感知质量的完整证明。负例 PSNR 为 N/A。计时含文件读写、编解码及指标计算，受同机任务影响，不作为吞吐量承诺。样本和载荷数量有限，不能据此宣称总体误报为零或 JPEG 75 是任意图片的保证阈值。

## 需求验收映射

- AC-001：internal/blind 及 bench 均为独立标准库实现；CLI/API 复用既有框架，无 Python、OpenCV 或上游项目依赖。
- AC-002：逐例复制比对 SHA、前后原图比对、只读原图与独立输出目录；文件 API O_EXCL 和别名负例，拒绝覆盖。
- AC-003：中文/ASCII 载荷、固定夹具、PNG重新编码、满34字节、最小容量与非零 origin 回归；容量不足和文本超限明确报错。
- AC-004：三类真实照片、三个 JPEG 档位报告；结果与边界如上，未泛化为所有图片。
- AC-005：无水印/错误密钥、篡改载荷、版本/长度校验和损坏图片路径；有限负例的拒绝不当作总体误报率估计。
- AC-006：缺省 legacy 不变；HTTP 测试缺密钥不影响 legacy；真实服务浏览器新旧模式都可操作，新模式结果有 algorithm 与校验标识。
- AC-007：报告区分合成离线夹具和三张下载照片，保留来源/哈希/参数/耗时/画质；裁剪/缩放/旋转/截图/拍屏未作为本版支持或实测通过项。

## 交付与边界

密钥仅服务端环境配置；单密钥 v1 不包含密钥库、轮换 UI、任务数据库或接收人溯源。输出不保留 EXIF/ICC，需方向修正的图片先规范化。HMAC保护载荷而不是整图，也不提供文字加密或防删除保证。两个并发处理槽配合 8 MP/50MB/请求限流限制资源，忙时可重试。

[当前新模式界面](../../../image/go-blind-extract.png) 已视觉检查：模式、限制说明、结果及载荷校验标识可见，使用既有满高侧栏和内容滚动布局。截图显式作为产品文档入库，不包含生产密钥。
