对应已确认REQ-001/002，按核心/运行时/API/UI切片实现；不缩减C～G范围。B已提交4ec6459且验收16项浏览器/race/vet，C从独立模块继续。

## PDF页级核心

- 使用pdfcpu v0.16.3作通用PDF对象解析/写入，Apache-2.0，不引入blind_watermark及Python运行时。其当前安全版本要求Go1.26+，同步go.mod与README最低构建要求；开发环境Go1.27.1。固定版本与依赖校验和，随分发保留许可证。
- 本平台自行实现`pdf-page-v1`页级标识协议：页面对象中的专属字典字段保存版本、文档/页标识、页号、正文、原始文件摘要、服务端时间和key标识，加域分离HMAC。不是旧PDF尾注释，不依赖正则寻找/插入页面。
- 标识认证仅说明标识由持钥服务签发，包含的源摘要为签发时原件身份；不等同当前整页视觉内容签名。保留页面对象可提取，重排/打印/截图/重制可能去掉或搬移标识，不宣称抵抗这些处理或证明泄露者身份。
- 选择`all`/空或`1,3-5`等页码，闭区间、一基、去重排序；页码越界/倒序/语法错误拒绝。可跳过封面；选空拒绝。文字模板支持{page}/{pages}，每页可覆盖，正文UTF-8≤500字节、不含控制字符，最多500页。
- 只在选中页面写入；所选页面存在本协议字段时默认拒绝覆盖，未选页原字段保留。原文件始终只读；输出写新临时文件，完整重读/结构校验、页数与逐页期望标识核对成功才提交，附JSON报告与输出SHA。最终报告准确区分未标记、有效标识、未知key和无效/损坏标识。
- 加密/损坏/超限明确拒绝。已有数字签名的文件不改写，避免破坏签名有效性；表单/链接等既有结构不主动扁平化或执行。stateless/offline配置，不读用户pdfcpu配置、不启用外部图像/网络资源、不运行PDF脚本。
- 初始限额：50MiB输入、128MiB输出、500页、10万对象/交叉引用项、递归32层、4MiB单对象、50MiB编码流、32MiB单流/页内容解码、800万像素/32MiB图像。关闭全流解码和优化，沿用两个全局处理槽并加context超时。解析器限制是具体资源边界，不冒充进程内存硬隔离；实现/测试发现需要收紧时记录而不静默放宽。
- 真实多页/表单测试样例，先复制原件再操作，最终逐页重读，Poppler渲染检查版式与未选页；损坏/加密/签名/篡改/异团队key均有负例。

## 目录/ZIP核心

- FileBatch为独立异步任务；逻辑相对路径与随机物理文件名分离。浏览器文件夹/多文件与ZIP输入走同一有界清单，保留目录结构，现有格式逐项真实处理/最终提取核验；PDF调用上面的逐页核心。图片的实际模式/Office兼容标识边界在结果报告标明，不把兼容元数据说成Go DCT认证。
- 初始边界100个文件、每文件50MiB、累计输入/ZIP展开128MiB；ZIP先检查EOCD/central directory预算与条目数，随后再使用标准库读取，拒绝不支持的ZIP64、多卷、加密、重复/绝对/穿越/反斜杠路径、符号链接/非常规文件。实际解压计数与CRC验证，不仅信任目录声明；Office内部ZIP同样预检。
- 上传/预检先固定原件摘要、路径与处理参数；逐文件状态/错误可见。正式运行可取消，原件不被覆盖；成功输出与失败报告同时准确呈现，失败项可独立重试。改参数须新建任务，不拿旧成功项冒充新尝试，也不重新处理已成功文件。
- 输出ZIP路径保持安全相对目录，扩展名变化/同名冲突在处理计划中明确解决，拒绝静默覆盖；清单列原名/原摘要/实际算法/输出路径/输出摘要/最终验证/失败原因。

## 协作、审批和生命周期

- 按团队存加密任务元数据、私有输入与成品；授权/并发/存储边界复用A/B。新资源状态明确 preparing/ready/queued/running/completed/partial/failed/cancelled/interrupted，进度来自实际文件；重启恢复为可观察中断并清理未提交产物。
- 将B的审批快照核心抽取为有类型的资源引用（image-job/file-batch），保留已写入图像审批和原API兼容。新文件任务的快照包含文件摘要/路径、逐页计划/文字、算法/输出要求等稳定输入；重试计数/运行结果不参与摘要。
- 受审批团队对文件批次同样“服务器预检计划 → 提交 → 独立审阅 → 执行”，不能用旧入口绕过。PDF/Office处理计划预览明确是服务器解析的页码/文件/参数清单，不冒充服务器渲染的页面图像。审阅凭证绑定资源类型、账号、revision与快照；执行/下载复查当前审批和权限。
- 输入准备期/成品留存、总磁盘、队列、失败重试与清理都须在实际运行时落实并可观察，沿用既有有界策略；最终配置/状态字段在实现后补充，不拿文档代替代码。
