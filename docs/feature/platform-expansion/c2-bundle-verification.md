# C2：有界ZIP/目录接收核心

新增`internal/filebundle`，只负责安全清单、解压/复制和实际指纹，不负责正式水印生成。C任务持久化、审批桥接、API/UI仍未交付。

## 实现

- 标准库zip.NewReader分配条目表之前，先用最多65557字节尾部扫描EOCD，再逐个检查central directory固定头/长度/计数/总预算；拒绝ZIP64、多卷、加密、非常规压缩方法、截断或矛盾目录。
- 默认100文件/1024目录项、128MiB压缩输入/实际展开、单文件50MiB、central目录1MiB；Limits可显式收紧，硬边界拒绝无限配置。Office内层包另有4096文件/8192项、50MiB输入/128MiB实际展开与4MiB目录预算，留给后续处理器预检。
- 逻辑路径最多512字节/16层，拒绝绝对/穿越/反斜杠/控制字符、流名/常见Windows设备名与尾部点/空格。重复路径、Unicode规范等价/大小写折叠冲突及文件-父目录冲突均拒绝。原Unicode拼写保留。
- 符号链接/特殊文件不进入暂存。所有物理文件名为随机ID，根目录0700/文件0600，逻辑路径从不作为磁盘拼接路径；不恢复来源权限。ZIP显式空目录可保留为清单，浏览器文件列表天然只提供文件及相对父目录。
- 校验声明大小只是前置筛选，复制时仍逐块检查实际文件/总字节、context与CRC；失败/取消删除整个新建暂存目录，已有目录不复用/不删除。原ZIP/原文件只读。返回实际SHA-256/字节与显示路径，物理路径不序列化为JSON。

## 验证

`GOTOOLCHAIN=go1.26.0 go test -race ./internal/filebundle`通过（3.200s），同包vet无诊断。

用例含真实Deflate/Store混合归档与Unicode目录、显式空目录、随机私有文件名/权限与源ZIP不变；穿越/绝对/盘符/反斜杠/空段/设备名/数据流、重复/大小写/NFC冲突/文件父子冲突；符号链接/FIFO（含伪装目录）；EOCD计数/磁盘/ZIP64/加密/长度和central预算、截断；第二个文件CRC错误使已写第一份也整体回滚；伪造展开大小与实际字节上限；目录输入源不变、链接拒绝及取消清理。

临时日志`/tmp/workspace-c2-bundle-{tests-final,vet}.log`。接收层通过不代表文件水印处理或整个C完成。
