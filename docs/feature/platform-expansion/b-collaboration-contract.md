# 批次B：通讯录、共享策略与审批执行契约

本文件细化已确认REQ-003/008，不缩减完整进度板。A完成后继续B，C～G保留。

## 通讯录

- 每团队独立Contact：随机id、team_id、recipient_id（UTF-8≤64字节）、name（≤128字节）、groups（≤10组，每组≤32字节）、revision、updated_at。名称/组不允许控制字符，组排序去重；业务ID在团队内唯一。
- 初始边界：每团队100组/1000联系人、导入1000行/1MiB；存储仍受全域16MiB及安全撤权预留保护。制作名单仍沿用20名接收人/16KiB，不能用通讯录选择绕过。
- 角色：read可查询，produce可新增/编辑/删除/导入；所有操作判团队，revision避免覆盖。CSV导入header为recipient_id,name，可选groups（|分隔），整组先校验；重复/已有ID冲突拒绝，不静默覆盖。可编辑单项后重试。JSON导出保真；CSV导出对公式单元格安全转义并说明差异。
- POST /recipients/search（q/group/page/page_size）、POST /recipients、PUT/DELETE /recipients/:id（revision）、POST /recipients/import、POST /recipients/select（≤20 IDs，返回当前快照CSV及摘要）、GET export。
- 前端独立通讯录/分组页面，查询/表格/编辑/导入/导出；批量副本、多图任务使用共享接收人选择器明确“填入当前名单”，调用原change清旧计划。只复制当前名单快照，不让历史分发随通讯录改名。

## 共享策略

- Policy包含team/id/name/revision、append-only版本（初始最多20版）、published版本指针；每版保存规范PolicyContent及SHA、创建人/时间。共享内容为模式/文字模板/样式/Logo布局标量/输出/质量，不接收Logo文件、源图、逐图避让或具体密钥。
- owner管理草稿/版本/发布/回退；operator/reviewer可用已发布版本。发布/回退改变指针而不重写历史版本。明确应用才改变表单并清旧预览，涉及Logo须重选。
- 保留本机策略，但其浏览器key按当前账号+团队隔离；原管理员personal使用旧key兼容，不自动把私人策略发布到团队。
- 每个写接口revision和内容严格验证，所有版本/变更事件与加密数据同一提交。

## 审批

- Team增加require_approval配置，由owner显式设置，personal旧空间保持原行为。设置后该团队的正式生成/分发必须经门禁，不能绕过原单文件/双水印/批量API。
- image-job先创建/上传固定源图与逐份渲染输入，预览就绪后请求审批。审批绑定服务端解析的不可变Job快照：team/job/operator/created_at/key/算法/源图与每份输入摘要/名单/样式/艺术层/输出/质量。排除进度、上传标记、重试次数等运行态；不信任客户端提交的“已验证”或快照散列。
- reviewer/owner可审批其他人的请求，请求人不能自批；批准、拒绝、撤回有revision/理由/事件。执行时再次比对当前快照、审批状态和审批人当前权限；输入改动或审批权限撤销失效。
- 按实际上传输入提供有界缩略图供审阅，不能用未经服务端核对的客户端截图。生成start/retry及成品分发在后端门禁；取消不要求批准。
- 对暂不接审批流程的旧直接生成API明确返回approval_required并在UI引导使用任务流程（单图也可），不能只隐藏按钮。C的文件/PDF运行接同一资源快照协议后才开放受审批团队对应生成，未接入前不得绕过。
- 仅无完整成品输出的受控预检/实验可在审批前执行，缩略图有界，不能把审批前的full output借报告交付。
- 一个团队策略不能阻止有原件的人在平台之外处理，环境管理员仍是受信引导身份；审批约束的是指定团队接口与记录，不宣称通用内容防泄露。

## 测试

API/领域：跨团队、重复与冲突导入原子性、group查询、历史快照不变、发布/回退/非法艺术层、并发修订；审批自批拒绝/撤回/改参数失效/角色撤销/直调用生成拦截/实际输入预览与最终start。浏览器：从库选人实际生成并追溯、共享策略双人使用、两身份真实审批、手机英文暗色；旧流程回归。所有批次完成再统一判断目标完成。

### 审批执行点补充

- 后台队列与HTTP门禁同时校验。Delivery Manager注入可选授权函数，在入队、真正领取处理、成品提交前及下载时检查审批/当前角色；旧个人空间不配置此函数。队列期间撤回或撤销审阅权限不能凭早先start继续交付。
- 工作区保存服务端计算的稳定Job摘要：去掉upload token、运行状态/质量/尝试次数，保留原图/渲染输入的身份、每份独立载荷及名单、模板/布局/输出/质量策略。上传只允许匹配固定摘要。提交审批前要求输入上传完整；实际文件检查及缩略图来自delivery私有暂存目录。
- 创建者和发起者均不得审批自己的任务；审批执行时重新检查请求人制作权限与审阅者审批权限。撤回及新申请均按revision更新并保留事务事件，队列失败使用明确approval_required状态码。
- 展示预览每次只返回256px有界JPEG，读操作不暴露原素材路径或任意文件；跨团队/未知source/copy拒绝。下载仍由现有成品校验与留存控制，过期原素材不可伪造重新审批。

- 批准须附5分钟预览凭证，由服务器在真实私有输入缩略图响应中以X-Review-Token返回，HMAC绑定当前审阅账号、团队/任务、审批revision与快照。批准接口校验凭证；伪造/过期/换人/旧审批版本拒绝。凭证仅内存保存，不在URL/浏览器持久存储中传递。它证明服务器曾提供预览，不证明人已逐项阅读。
- 原15分钟输入留存与1小时ZIP边界保留；跨重启仍须按旧规则重新上传同一固定输入，审批绑定内容身份不绑定可轮换upload token。审批记录最多1000条/团队、每条40次变更，预留最后一次撤回。
