## 背景与目标

当前为 Go 服务直接提供原生 HTML、CSS、JavaScript 的单页工具，仅有添加与提取水印，无账户体系。升级为具有统一导航、身份入口和个人显示偏好的水印工作平台，保留现有文件处理能力。

## 待确认假设与范围边界

| ID | 推荐默认方案 | 原因及影响 |
| --- | --- | --- |
| ASM-001 | 第一版为部署者配置的单管理员账号，凭据通过环境变量提供；不提供注册、找回密码、用户管理和角色系统。 | 当前无账户存储；真正的多用户系统需要另行定义账号来源与权限。 |
| ASM-002 | 使用服务端会话与 HttpOnly Cookie；不在浏览器保存密码；账号未配置时拒绝启用受保护功能并提供配置说明。 | 确保登录具有实际访问控制。 |
| ASM-003 | 现有水印 API 路径及成功响应保持，新增登录要求；已有 API 客户端需要先登录并携带 Cookie；CLI 不受影响。 | 这是新增登录带来的兼容性变化，须明确接受。 |
| ASM-004 | 工作台提供真实功能入口及格式说明；不虚构统计、历史记录或团队数据。 | 当前无任务历史或数据存储接口。 |
| ASM-005 | 不增加数据库、SSO、批量处理、云端文件库和运营管理模块。 | 这些内容未在原始请求中明确提出。 |

## 失败与恢复

- 会话失效时返回登录界面并说明原因；重新登录后可继续操作。
- 上传错误、网络错误及处理错误可见，不自动重试文件处理请求。
- 提交失败保留当前输入；主题、语言切换不重置当前表单。
- 文件沿用当前临时处理方式，不新增长期保存。
